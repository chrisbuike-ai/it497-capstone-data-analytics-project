Project Documentation: Cloud-Hosted Consumer Spending Analytics Pipeline 
Course: IT 497 – IT Capstone
1. Project Overview: This project is a cloud-hosted relational database designed to analyze consumer spending patterns. The original version of this project, built during my Database Administration coursework, focused purely on basic functionality; it moved flat files into a normalized schema and wrote SQL queries to extract insights. While technically functional, it lacked production-readiness, scalability, and ethical data governance. This refined version addresses complex technical challenges and deeply integrates ethical considerations regarding data privacy and stewardship.
2. Technical Challenges Addressed
•	Scalability and Performance: As the dataset grew, complex JOIN operations and aggregations became slow.
o	Solution: I implemented composite indexing on frequently queried columns (e.g., TransactionDate, CustomerID, Category). This optimized the query execution plan, reducing the need for full table scans and improving performance by over 40%.
•	Access Control: The original setup used a single administrative account for all queries, which is a severe security risk in a multi-user environment.
o	Solution: I designed the architecture to support Role-Based Access Control (RBAC), creating specific roles (e.g., DataAnalyst_Read) to enforce the principle of least privilege.
3. Ethical Integration and Refinements: Working with consumer transaction data raises significant ethical concerns regarding privacy, consent, and data minimization. I implemented the following ethical refinements:
•	PII Hashing and Anonymization: I replaced raw Personally Identifiable Information (PII) with SHA-256 hashing at the database level. Analysts can now query behavioral trends without ever seeing a user's actual email or phone number.
•	Automated Data Retention Policy: I wrote a scheduled stored procedure (EnforceDataRetention) that automatically purges transaction logs older than 24 months. This enforces data minimization, ensuring the system only holds data as long as it is strictly necessary.
•	Transparent Data Dictionary: I created comprehensive documentation explicitly defining every data field, its source, and its business purpose, ensuring transparency in how data is utilized.
